A local development workspace that reviews your own JavaScript, TypeScript, or Python project and uses Gemini to teach the concepts behind detected findings.

## Start

Requires Node.js 22.13+ and npm. Run npm install, then npm run dev -- --port 3001. On Windows, Start-Catalyst.cmd starts the same local preview.

Open http://127.0.0.1:3001.

## Workflow

1. Choose a project folder. The workspace starts empty; no sample project or preset metrics are loaded.
2. Inspect findings, search by title or path, and filter by priority.
3. Select a finding and ask Gemini to explain it, suggest a next step, or ask a comprehension question.
4. Mark concepts you understand. This is your own session record and does not resolve a finding.
5. Edit files in your editor, then use Review changes and select the same folder to compare snapshots.
6. Open Impact Lab to trace JS/TS import dependencies, predict the reach of a change, reveal evidence paths, and export an impact report.
7. Explore the file inventory or export the current findings as Markdown. Each successful AI response also shows actual Gemini token usage.

Open project begins a fresh session even if the folder has the same name. Review changes explicitly compares against the current snapshot and checks the folder name. Browsers do not expose absolute folder identity, so choose the same folder when comparing.

## Data and limits

All counts, locations, sizes, timestamps, comparisons, and check results come from selected files and actual imports. Finding titles and priorities are rule definitions, not invented project results. Explanations are generated by Gemini on demand. There are no prewritten lessons, fixes, generated-file templates, or production sample data.

Source files remain in browser memory and are never executed. Reloading or closing the project clears the project and session history. No source, filenames, or credential values are sent to Gemini: only the finding ID, language category, suggested stage, and question intent. The server supplies a curated reference summary to ground the model, not a canned answer.

Import limits are 500 supported files, 10 MB total, and 250 KB per file. Generated directories, dependency directories, and unsupported file types are excluded. Oversized supported files produce a partial-review notice.

These are educational heuristics, not compiler or security scans. Test and CI presence does not prove execution or correctness. GitHub sync, continuous watching, whole-program semantic analysis, authentication, and persistent project storage are not implemented.

## AI setup

See [AI-SETUP.md](AI-SETUP.md). The Gemini key stays in the ignored server-only .dev.vars file. The mentor is restricted to loopback hosts until authenticated hosting is implemented. A missing key or provider failure leaves local findings available; no mock answer is substituted.

## Main files

- app/page.tsx: empty state, review workspace, file explorer, and session history.
- app/globals.css: responsive workspace styling.
- lib/project-import.ts: bounded folder import and exclusion accounting.
- lib/analyzer.ts: deterministic checks with no network or execution.
- lib/review-tools.ts: snapshot comparison and evidence-only report export.
- app/components/AiMentor.tsx: on-demand Gemini guidance and provider token receipts.
- app/components/ImpactLab.tsx: dependency exploration and prediction/reveal learning.
- lib/impact.ts, lib/impact.worker.ts, lib/impact-tools.ts: local AST dependency graph, cycles, reachability, and report export.
- lib/server/mentor.mjs: server-only Gemini adapter, reference selection, validation, and request limits.
- tests/: import, analysis, and provider-mocked integration tests. Test fixtures are not imported into the app.

## Validation

Run npm test, npm run typecheck, and npm run build.

For a restricted environment that blocks test subprocesses:
node --test --test-isolation=none tests/analyzer.test.mjs tests/mentor.test.mjs tests/project-import.test.mjs tests/impact.test.mjs

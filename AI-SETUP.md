# Enable Catalyst AI mentorship

## Local configuration

1. Open `.dev.vars` in the Catalyst folder. This file is ignored by Git. Never share it or paste your key into chat.
2. Set `GEMINI_API_KEY` to your Gemini API key from https://aistudio.google.com/apikey. Leave `GEMINI_MODEL=gemini-3.5-flash-lite` unless you choose another Gemini model with structured-output support.
3. Stop the local server with Ctrl+C and restart with `npm run dev -- --port 3001`, or use Start-Catalyst.cmd.
4. Open http://127.0.0.1:3001, select a finding, and click **Check configuration** in the AI mentor section. “Key loaded” confirms only that the server has a key, not that it is valid.
5. Click **Explain with AI**. A successful response appears with model attribution. Requests use the quota/billing of the configured API key.

The key stays server-side. The application does not include an API-key form, log the key, or return it in status responses. `.dev.vars.example` is a safe blank configuration template.

## What gets sent

The browser sends exactly four fields: finding ID, language category, suggested stage, and question intent (explain, next step, or quiz). The endpoint rejects extra fields. No project names, file paths, file contents, custom user text, or detected credential values are included.

The server selects a curated reference summary for that finding, then calls the Google Gemini generateContent API using structured JSON output. Provider data handling depends on your Google account and service terms; see the Gemini API terms linked below.

The AI receives neither tools nor permission to execute code. It cannot edit files or change a practice score. Responses are validated and rendered as plain text. The reference URL is chosen by the server, not generated by the model.

## Grounding and limits

This is reference-grounded generation with deterministic reference selection. It is not an embedding search engine. The summaries are curated guidance, not live copies of entire documentation pages. AI output may still be incorrect; review it before following it.

Access is currently limited to loopback hostnames. POST requests must have the exact same Origin and JSON content type. The local worker permits one in-flight request and five starts per minute. Limits reset with the worker and are not distributed production quotas. Do not expose this endpoint publicly: authenticated access and durable per-user usage controls are required before deployment.

Request payloads are bounded to 4 KB, output to 4,096 tokens (including any thinking tokens), and provider requests time out after 45 seconds. Invalid keys, quota limits, refusals, malformed output, and timeouts leave local findings available. The app does not silently substitute mock AI answers.

## Verification

`npm test` runs deterministic analysis and provider-mocked integration tests without needing a real API key. These tests verify protocol handling; they do not establish live model quality or account access.

A live connection remains unverified until **Explain with AI** succeeds using your configured key. To test manually, import your own project and choose a detected finding. Check that the response addresses that finding and avoids claiming to have inspected or fixed your source.

## Token receipts

Each successful response now includes sanitized Gemini usage metadata. The UI shows input, output, thinking, and total tokens; missing counters appear as an em dash. These are provider counts for that response, not estimates or an account-wide billing total. Failed requests may consume quota without a receipt. Configuration checks and the local Impact Lab make no Gemini generation calls.
